# Storage and delivery operations

Before source inspection for any authorized multi-step archive, review, adoption or handoff, read [recovery and diagnostics](recovery-diagnostics.md) and begin its required workflow session. Keep that session through the operation.

Read for the requested creation, organization, adoption of external material, complete map or project delivery. The main Skill authorization and evidence rules still apply. When this operation includes archival intake or review, also load [archive and review operations](archive-review-operations.md). For interruption recovery, load [recovery and diagnostics](recovery-diagnostics.md).

## Storage and delivery

Ordinary verification, archival intake and status updates use the incremental business routes and selected evidence described in SKILL.md. They do not select the complete project/map upgrade below. Keep an existing reading view labelled with its actual snapshot until an explicitly requested reading update is prepared; do not describe a stale view as current. Full audit, consolidation, complete reading and exchange delivery are separate scopes, not automatic prerequisites for saving research. Existing complete-upgrade tools still perform broad conformity checks; do not invoke them to complete ordinary archival work or pretend those checks are incremental.

- For a requested complete project/map upgrade, use `scripts/crs_project.py upgrade` and [project layout](project-layout.md). One shared model drives the substantive research homepage, Obsidian entrance and AI locator. The browser launcher opens the research homepage directly. Bind the existing sole formal library, complete current reading, source-reviewed formula notation and full manuscript translations; render actual pages, inspect the visual evidence, then resume the same guarded publication operation. Missing browser or visual evidence is an unfinished operation, not whole-task success. Preserve safe historical links and physically organize authorized material with a reference map and explicit exceptions.

- For a new library receiving an existing project, use `init --receive` followed by `import`; the source package supplies the original primary identity. Create a new research question with `init --objective-file` when starting distinct research.

- Use one clearly named enclosing research-project folder. Its top level contains the readable research map; keep the formal library in a child directory (for example `研究数据/`, or the existing CRS data-directory name). Keep working material in its declared project role. The project entrance links to external derived reading views and deliveries; their complete bytes and packaging scratch stay outside the enclosing project. The enclosing folder is navigation, not a new authority store. Resolve CLI commands to the nested formal library; never initialize over an existing project. For an explicitly requested reorganization, verify paths and unchanged HEAD/object hashes, preserve originals and incoming links, and move the map and library together without re-reviewing unchanged research.

- Use the bundled classic browser template for newly created or updated readable maps unless the user chooses another design. Follow [web reading](web-reading.md): fixed ten-section navigation, a clear research question, completion standard, progress and obstacles linked to exact records; complete English manuscripts (proofs and correctness arguments, algorithm descriptions, experiment reports) with full remembered Chinese reading. Inspect unmarked formula notation as well as renderer errors, across headings, lists, tables and both languages. Keep research content and original review scope intact. Low-level `map`, `finish` and web structure checks remain available, but their pending or unchecked browser state cannot complete a full upgrade request.

- Local `map --out` defaults to Obsidian format: native block navigation and Markdown reading views for stored objects. Use checked external delivery references at the project entrance and relative links within the external delivered view; never treat extensionless object-store files or HTML IDs as Obsidian notes. Reading views are derived displays, not editable research records or newly reviewed evidence. Large/binary objects must show their availability and exact retrieval identity, without pretending their body was embedded. Use `--format markdown` for a generic Markdown map.

- For maps carrying formulas, pseudocode, code, tables or figures, use $obsidian-vault-notes and [formula presentation](formula-presentation.md). Convert plain-text formula notation through reviewed exact presentation replacements before summaries, keep code and pseudocode as literal code, and preserve source objects. A zero-formula check cannot certify formula-bearing prose. Do not claim rendering from structure checks: validate final bytes, render every formula, and inspect prose/table layout before delivery. Local map/finish commands block recognizable unconverted or malformed formulas and report rendering as not checked until actual rendering occurs.

- Keep readable map exports, exchange ZIPs and every volume of a delivery set outside the entire enclosing project. Reject linked/reparse aliases into it before creating output. When archive delivery is requested, use `finish` after the required review to produce a new local archive directory with a complete `map.md`, a `reviewed-handoff.zip` or indexed `reviewed-handoff.parts/` set, and a receipt naming the actual artifact. The local map may contain unreviewed history; only the reviewed ZIP or complete indexed volume set is the external research handoff. Export already verifies the package it creates; do not repeat that verification for unchanged bytes. Temporary reproduction copies belong in an owned external directory; preserve required evidence, then clean the owned copies before closing the workflow.

- If publication is interrupted, recover the original operation ID. Do not delete locks, rewrite HEAD, or invent a fresh operation ID merely to bypass a conflict. A newer unrelated HEAD must be preserved.

- Deliver reviewed material with the map, navigation, exact record/report links, conditions, and evidence availability. Large evidence may be referenced; required review reports remain included. Never hide unreviewed research inside a generic evidence attachment.

- Before handing a package to another party, inspect its content and reported sources for inappropriate local or private material. Portable derivatives must be reviewed as new exact bytes; do not silently rewrite originals.

- A package records its source snapshot. It does not automatically receive future corrections. Tell the receiver how to query the included records and return new records and evidence without replacing history or taking over their research direction.

## Measure and reduce intake I/O

Use `ingest PROJECT --submission INTAKE.json --operation ID --expected-head SHA --metrics` for invocation-local aggregate counters and inclusive timings. The metrics contain no paths or contents, and are separate from optional host Skill observation. Hashing, resolve, path checks, file copying, staged bytes, temporary directories and fsync are instrumented. Nested durations must not be added to wall time. The reported byte scope excludes uninstrumented metadata reads; unknown peak memory is explicit. These measurements are not a historical performance comparison or evidence that a full archive completes within a fixed time.

One intake transaction shares a private scratch directory, uses unique staged filenames, and retains file flush/fsync and atomic publication. Before copying an already archived identity, fully verify its stored bytes and hash the source again; missing content follows normal copy-and-hash publication. A corrupt target fails instead of being silently overwritten. A copied stream must match its expected identity before publication. Scratch cleanup is owned by the active context; process-crash recovery still follows the existing prepared/committed protocol, and this does not add a power-loss durability guarantee.

Compare identical synthetic input and machine/code versions, separately reporting first and repeated reads without calling OS caches cold unless they were controlled. Test corruption, a source changing between reads, duplicate operations and interrupted publication before a large real-data comparison. Such measurements never write to source archives or research records.

## Caching boundary

Evidence arrays are kept as declared; they are never replaced with summaries. An asset collection with an independent index would need a separately validated conversion that keeps every member hash, size, role, name and locator, exact reopening and complete export. There is no persistent verification cache and no incremental display invalidation. Any display reuse must bind body, source revision, template, renderer, referenced resources and state; body hashes alone are insufficient. Measure existing page reuse and audit reuse before adding another mechanism.


## Whole-project recursive content coverage

Resolve the actual enclosing project before an operation. Use the global `--project-root ENTIRE_PROJECT` argument when the nested formal store is not unambiguously bound by `.crs-project.json` or its `scope.json` binding; never accept a narrower override. New initialization persists the scope. Existing bindings and research HEAD/object identities are never silently rewritten.

`content-audit SCOPE` reads current bytes and recursively compares ordinary files, archive containers and decoded members, including extensionless content objects, nested archives and files in different ZIPs. It excludes no project role. The scanner bounds total expanded bytes, member count, nesting and ZIP metadata allocation; it rejects encrypted/corrupt/unsupported containers, links, escaping members and incomplete coverage. Its guarantee covers recognized signatures and declared archive formats under cooperating-writer quiescence, not identification of every conceivable binary format. Uncertain formats need a decoder before claiming complete coverage. Store writes also check staged members before publication. Metrics separately expose this additional scan cost; no whole-project speedup is claimed.

Existing duplicates are a consolidation backlog for the complete audit, not a precondition for incremental business operations. Do not exclude directories from a complete audit. Ordinary writes instead verify the objects they reuse and all new candidate bytes, with recursive checks on new containers. They do not rescan unrelated historical directories or decode all old containers. Existing top-level CAS objects with identical hashes are reused after byte verification; source references and record identities remain distinct. Duplicates hidden only inside historical containers or non-CAS files may remain undetected by this incremental route. Do not claim global uniqueness from write success. Exports verify their selected research closure and complete external delivery without requiring source-project conformity. Full `audit` and `content-audit` remain strict and can still fail on historical duplicates or incomplete decoding. Cold-location writes use the same incremental integrity boundary, so a consolidation can record recoverable intent without first satisfying the audit it is meant to repair.

For an explicitly authorized complete consolidation, preserve one physical object and every original path, source, parent container, member path and historical relation in reference manifests. If an original container must remain byte-exact, retain it in external cold storage with identity and resolvable provenance. ZIP documents and compressed datasets receive no suffix exception. Do not pad, timestamp, rename-and-rehash or semantically rewrite evidence to force a different identity. Consolidation requires the applicable project authorization and verification of references and unchanged research identities; updating this Skill alone does not authorize moving a live project.

## Ranked size-bounded export

`export PROJECT --out EXTERNAL.zip` defaults to a 512,000,000-byte final ZIP ceiling and a 460,000,000-byte optional asset budget. `--max-zip-bytes` can choose a smaller ceiling, never a larger one. Required review reports rank first; optional evidence ranks by importance, then future research relevance, with deterministic SHA ties. Default scores use evidence roles, future-work hooks and reuse counts; they are metadata heuristics, not claims of research quality or a new review. An optional `--priority-file` maps exact asset SHA identities to `importance` and `future_research` integers in 0..100 plus a substantive `reason`. Prefer explicit project priorities when available. Preserve required records, report history, research dependencies and the exact reviewed summary/locator of omitted evidence.

The exporter measures the actual ZIP. If it exceeds the ceiling, it distributes unique logical files into `EXTERNAL.parts/part-NNNN.zip`, each measured under the same ceiling. `parts.json` binds the exact volume/member hashes, ranking and use instructions; all volumes form one logical reviewed handoff and contain no repeated payloads. Retain the whole set. `verify-bundle` and `import --bundle` accept the directory, reconstruct the logical exchange only in owned external scratch, and reuse the canonical data validator without executing bundled code. Missing, changed or extra volumes fail. The project and this external set are independent uniqueness scopes; within the set, ordinary files and all ZIP members are checked together.

Volume splitting preserves whole exact logical files. If a mandatory single payload cannot fit even alone, export stops before publishing; it does not omit the report, split it without a reconstruction contract, or emit an oversized ZIP. First establish an applicable reviewed external reference or a separately authorized chunked-data protocol. This limitation is explicit and never presented as successful size-bounded delivery. Optional large evidence may use its already reviewed exact external reference.


## Export preflight and consolidated repair

Run `export-preflight PROJECT --out EXTERNAL-PREFLIGHT.json` before a substantial export repair. This reads one source snapshot and uses the same reviewed projection as export. The complete external report captures all detected record/review path occurrences, candidate record revisions, transitive strong-dependency revision candidates, asset counts, JSON limits and a conservative manifest estimate. The CLI returns counts and a bounded preview. A blocked preflight still writes its complete report; read that report by fields rather than rerunning the scan to recover omitted details. Source bytes and HEAD are unchanged. Metadata estimates and a clean report do not verify missing material, report contents, final map size, compressed size or the truth of research claims; remaining checks are explicit.

Use the report's snapshot while preparing one consolidated revision plan. For each path change, preserve the source revision and research identity, assess whether a suspected drive prefix is actually TeX, and review the exact derivative. Do not suppress path detection or rewrite source bytes merely to make export pass. Build an old-to-new revision map, close strong dependencies and correction targets transitively, and order the affected revisions by their dependencies before ingesting. Detect cycles or unknown equivalence before publication. Recheck candidate status with the existing intake/review prediction. A dependency pointing to a nonportable old revision is unresolved even when its replacement already exists; do not silently remove the dependent from the baseline export closure. Semantic equivalence and review adequacy remain substantive review duties.

Check path findings, dependency closure, record/index capacities and required-report availability/budget together before expensive intake. Reuse verified unchanged research reviews only within their original scope. Ingest the complete planned batch, review the affected exact revisions, then compare the resulting export closure with the frozen baseline. Reconcile any changed HEAD or inputs. Assemble the delivery only after that comparison; do not create a large temporary projection as a diagnostic probe. If a capacity warning cannot yet be settled, name that gap before assembly.

Asset ranking builds one invocation-local asset-to-record index, counting each record once per asset. Record loading validates its excluded-reference list once per call. Neither optimization caches evidence verification, trusts filesystem timestamps, nor skips consumption hashes. JSON metadata has a bounded 256 MiB reader ceiling; referenced-only asset declarations have a separate 64 GiB ceiling and do not allocate those bytes. Actual entry, expansion and final ZIP caps are separate limits. Exact generated manifest/namespace and expanded payload sizes are checked before compression; a reader with smaller metadata caps can reject a large package.

Export verifies its own completed bytes. Reuse that receipt for unchanged output; a modified payload, source binding or generator invalidates the affected check. Report metadata traversal, evidence I/O, required review, repair/retry and assembly costs separately when measured. Raw archive size alone does not explain avoidable repeat scans. The bounded review response preserves a valid batch hash so response omission does not force another preflight or submission.


## Delivery sufficiency and readable maps

Apply this check to a requested research-project export or handoff. A deliberately selected-record exchange remains available when that is the user's requested scope. Do not silently narrow a project request to whatever the default exporter admits. This is an operational check of existing evidence and delivery usability, not a new research review or permission to change research direction.

### Select by research use before ranking bytes

Freeze the source snapshot and identify the main algorithms, important results, complete proof or argument texts with assumptions, experiment configurations and seeds, useful failures and open gaps from the existing project map and bounded exact record reads. Keep a compact coverage table in the external delivery work record, grouped by result or algorithm, not by every file. For each group record its exact revisions and original assurance, the materials needed to understand or check it, their actual included/referenced/missing availability, the smallest reproduction route and remaining limitations. Unknown sufficiency remains an explicit gap.

Inspect the relevant code entrypoints, imported project modules, configuration and data consumers to identify the frozen source commit, configurations, seeds, environment specification, final outputs and evaluation results, certificates, verifier and inputs required for each retained claim. An abstract or result statement does not replace the full proof or argument; a verifier without its required input is incomplete. Conversely, a byte-exact historical ZIP need not be physically repeated when all necessary decoded members and provenance are supplied. Decide whether large databases or archives are necessary from their use, not their extension. Keep original claim scope, conditional premises, failed routes and corrections visible.

Use filenames, evidence roles and default priority scores only to discover candidates. They do not establish that lower-ranked evidence is dispensable. Do not silently drop a required item for a size threshold, file-count cap, unfamiliar or non-English name, archive suffix or embedded local path. Resolve portability through the existing reviewed-derivative rules; if necessary bytes cannot be supplied, mark the affected group incomplete. Marking an asset optional in the exchange format does not make it optional for the user's research purpose.

Choose optional material only after the essential set is understood. Use supported priorities and budgets, then check the actual resulting manifest and members: a high score does not force inclusion. If the essential set does not fit one ZIP, use the supported indexed volumes; do not meet a preferred size by sacrificing it. Respect existing per-payload and expansion limits and report an unsupported case. Exact external references remain appropriate for nonessential or explicitly reference-based scope; they cannot support a claim that all essential evidence is available offline. Report the affected claim and retrieval method instead of hiding the omission among asset counts.

### Reconcile scope and verify the delivered copy

Compare the resulting reviewed projection with the frozen intended coverage. Account for every omitted important record and its affected conclusions, including exclusion caused by strong dependencies or review status. Complete authorized dependency/portability repair where possible. Otherwise preserve the gap visibly in the reading view and final delivery statement; never grant a review, delete a premise or hide an unreviewed body in an evidence attachment to make the package appear complete. Distinguish the full source-history map from the reviewed exchange map and label both snapshots and coverage.

Read the actual final package or complete volume set, not merely the source directory or a selection receipt. Reconcile the coverage table with member hashes and manifest availability. For computational claims, check that the declared entrypoint and necessary inputs can be located from the recipient instructions without a sender-only directory. Use the smallest appropriate verification/reproduction within authorized scope; reuse applicable unchanged replay evidence, and state what was not executed. Neither successful execution nor this coverage check promotes a research status. A failed or unperformed replay remains separate from byte completeness.

### Deliver a map that can be used

Use the existing browser-reading route for a complete project handoff and keep its canonical records unchanged. Provide a concise research entrance with the question, current progress, main methods, established and conditional results, manuscript links, failures and next gaps. Split long record and asset indexes into linked pages or use the existing bounded navigation; do not embed the entire asset inventory repeatedly in one giant entrance. A complete machine index may remain separate. A launcher or installation guide alone is not the research map.

From the actual external delivery copy, open the research entrance and follow a main algorithm, an important result, a full proof or experiment report and an omitted-evidence link. Check navigation, formula rendering, readability and availability labels, using the existing visual-validation rules. Supply all local rendering resources needed by an offline claim. A Markdown map's presence, byte size or heading count does not prove usability; a screenshot of an unrelated guide does not validate it. Missing visual evidence leaves map usability unchecked and cannot complete a full readable handoff.

### Report only the assurance obtained

Report separately: byte-integrity verification, substantive coverage, actual evidence availability, research review/replay scope, and map usability. Name important unresolved omissions prominently alongside the delivery link. Give included and referenced counts/bytes when helpful, but never use compression ratio, record count or a successful export receipt as evidence that the main research survived. When a check is incomplete, deliver any useful partial result with that limitation and continue the work already authorized; do not describe it as a complete project handoff.

These checks require substantive selection and observed recipient use. Existing export/preflight validators do not enforce the coverage table or independently determine semantic sufficiency. Do not claim a new machine gate from these instructions alone.

## Repairing immutable path-bearing history

When ordinary revision repair leaves reviewed original versions in the export projection, prepare one explicit `--portable-history PLAN.json` for both export-preflight and export. Follow the [portable history contract](data-contract.md#portable-history). Preserve source originals and history, ingest and substantively review exact portable derivatives, close transitive dependencies, then bind the plan to that resulting source snapshot. Do not reuse a review of different record bytes or suppress path detection.

The plan is not blanket permission to omit historical research. Account for every original in the delivery coverage table, inspect the full retained evidence, and retain informative historical qualifications. Export rejects unsupported replacement, evidence omission, and incomplete strong closure. Inspect the actual excluded-history map links in the recipient copy. Required evidence with local paths still needs its own properly reviewed portable derivative; record-level replacement alone does not repair evidence bytes.
