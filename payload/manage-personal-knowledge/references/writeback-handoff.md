# 受控写回交接

`manage-personal-knowledge`负责把经过检索和核对的发现交给`$obsidian-vault-notes`写入真实Vault。它不复制笔记技能的编辑、转义、链接或语言审校实现。

## 何时使用

用户明确要求“写回”“记录到笔记”“更新某篇笔记”时使用。只查资料、只读PDF、只回答问题，不建立写回包。

## 交接包

交给`$obsidian-vault-notes`前，逐项写清：

| 字段 | 必须说明什么 |
| --- | --- |
| 目标与授权 | 确切笔记路径或标题；用户允许修改什么范围 |
| 来源 | URL、Vault相对路径、PDF相对路径与物理页码、摘录、检索覆盖警告、截至日期 |
| 结论状态 | 哪些是预印本或技术报告、独立复现、形式化验证、同行评审发表，以及证据等级（`formal`、`certificate`、`exact_reproduction`、`bounded_empirical`、`numerical_evidence`）；不要合并成“已证实”；“代码能跑、测试通过”只说明所检查的边界 |
| 不可改动项 | frontmatter、封面或嵌入、wikilink、块标识、原文引语、链接到的详解笔记等 |
| 语义哨兵 | 写后必须仍存在或不得出现的文字、链接、状态标签、公式分隔符和出现次数 |
| 文章要求 | 文章类型、读者、局部语气、是否触发长中文逐句审校 |

来源不足时，把结论写成“尚未核实”或“只在索引文字中找到”，不要在写回时补成确定事实。

## 高风险写回

下列情形必须要求`obsidian-vault-notes`回传完整`EditAudit`：理论结果、复杂度界、基准数字或复现结论的状态、新闻或时效来源、长文章改写、已经含有块标识/嵌入/复杂链接的笔记、跨笔记改动。

审计至少应说明扫描范围、来源与状态措辞、Markdown哨兵、自然度审校、仍需人工判断的句子，以及实际运行的检查。`lint通过`只能说明对应检查没有报出风险，不能代替“中文自然”的判断。

## 失败归因

| 失败类型 | 典型信号 | 正确处理 |
| --- | --- | --- |
| 格式或序列化 | 反引号被转义、公式分隔符损坏、换行变化 | 停止写入或回滚；交给笔记技能的受控编辑与断言流程 |
| 来源或状态 | 把预印本写成同行评审，把“代码能跑、测试通过”写成科学结论，把单次运行写成可复现结果 | 回到原始来源，分开标注不同核验层级与证据等级 |
| 范围或链接 | 改掉块标识、误动封面、打断详解链接 | 检查不可改动项和语义哨兵；缩小编辑范围 |
| 验证覆盖 | 只检查新句、只说lint通过、未读当前文件 | 重新读取当前目标，做全篇冷读与写后窄检查 |

发现失败时，先说明属于哪一类，再决定补证、重写、恢复，还是请用户选择。不要用更多自动改写掩盖没有核实的结论。
