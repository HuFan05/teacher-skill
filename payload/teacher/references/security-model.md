# 安全模型

## 控制方向

先确立谁控制谁，因为其余一切都是在回答这个问题。

在普通的提示词式部署里，**模型是操作方**：它读了文档，然后自己决定做什么、自己输出给人。
装上 Teacher Skill 之后，判断与门禁归 Skill，调研仍由宿主 agent 用自己的工具完成：

| | 普通 agent 回答 | 经过 Teacher Skill |
| --- | --- | --- |
| 谁决定要不要反问用户 | 模型 | **Skill**：`need.decide` 的规则 |
| 谁写澄清问题的文字 | 模型 | **确定性渲染器** |
| 谁决定答案能否交付 | 模型 | **答案门**（`answer.validate_answer`） |
| 谁核对引文 | 模型自称 | **Skill** 在原位置重新读取 |
| 谁写用户看到的文字 | 模型 | **确定性渲染器**，模型文字只进带标注的槽位 |
| 谁能推进 `authority` head | 任意 | 只有绑定目标、归档、晋升、终局确认 |

具体到代码，控制权体现在这些地方：

1. **判断在 Skill 里。** 框定 → 规则 → 答案门 → 渲染 → 提交。模型在这些环节里没有一步可以选择流程分支。
2. **模型只能交出封闭结构。** 框定是八个键的分类与锚定读法，答案是声明的槽位；多一个键就拒绝。
3. **Skill 的读取受自己的配置约束。** 读取根、声明命令与网络策略来自配置；Skill 自己不扩大任何一项。
4. **写入只有一条路径。** 所有结构性改动都经过 `Store.transact()`；门禁在事务之外运行，被拒绝的操作根本没有进入写入。

**仍然做不到的**：宿主 agent 拥有通用工具权限，它可以不走 `frame-check` / `check-answer`，
直接在对话里输出文字或写文件。这不是本包能防止的——只能让它**可见**：存储有哈希链，包有校验和。

## 承诺边界

### 可承诺：拒绝时无副作用

`teacher.py` 与 `th.cli` 上的每一个写入都经过门禁。可承诺的性质是：

> 不合规的写入被拒绝，且被拒绝时 `authority` 与 `execution` 两个 head 都保持原值。

这条性质由三件事共同保证：所有结构性改动都经过 `Store.transact()`（比较并交换、提交后回读校验）；
门禁在事务之外运行，被拒绝的操作根本没有进入写入；记录的效果（`record_effect`）是推导出来的，不由任何地方直接赋值。

### 可承诺：进入答案的证据被重新核对

> 每一条被引用的来源片段都由 Skill 在其声明的位置重新读取：读不到记为 `declared`，读到了但内容对不上就丢弃；
> 答案末尾如实给出三类计数。

这条性质由 `_verify_excerpt` 保证：本地片段按读取根解析后重新打开磁盘上的当前文件，PDF 重新抽取文字，
URL 在网络策略允许时重新抓取；判定只有 `verified` / `declared` / `mismatch` 三种，没有第四种。

### 不承诺

上面的断言是**数据流性质**，不是语义性质。明确它不是：

- 它**不**声称答案内容正确。答案门证明的是“每条结论说清了自己依据什么、没有强于证据、引文确实在来源里”，
  而不是“结论为真”。`semantic_correctness_proven` 永远为 false。
- 它**不**声称能识别任意形式的语义伪装：换一种记号、翻译、编码、逐步诱导。
  判断“这段任意表述里是否夹带了不该给的东西”需要解决守卫本身想防的分类问题。
- 它**不**覆盖宿主 agent 在 Skill 之外完成的任何工作。

因此做法是：把可证明的部分收窄到能证明的程度，并把它说清楚；剩下的部分用
“结构化自报 + 独立复核 + 事后可检”来处理，而不是假装它被防住了。

## 机制

每一项都可以在代码中核对：

| 机制 | 位置 | 作用 |
| --- | --- | --- |
| 封闭键集 | `need.validate_frame_draft`、`answer.validate_answer` | 多一个键就拒绝 |
| 封闭枚举 | `constants` | 每个取值必须在词表内 |
| 读法锚定 | `need.validate_frame_draft` | 每种理解必须逐字引用用户原话 |
| 引文逐字节校验 | `answer.validate_answer` | 自称的原文必须出现在所引片段里 |
| 依据—证据一致 | 同上 | 来源类依据只能引来源片段，执行类只能引执行结果 |
| 强度—等级表 | `constants.MINIMUM_GRADE_BY_STRENGTH` | 结论不能强于证据 |
| 必写未知项 | 同上 | 证据不完整时必须声明未知 |
| 长度上限 | 同上与渲染器 `_slot` | 简短由程序保证，渲染器再查一次 |
| 确定性渲染器 | `render.Renderer` | 用户可见文本的唯一写者 |
| 固定失败串 | `render.render_ask_failure` | 失败只产出固定的话与封闭计数 |
| 失败码白名单 | `engine.safe_code` | 异常信息不越过边界 |
| 封闭操作词表 | `broker.OPERATIONS` | 全为只读；没有会改动的操作 |
| 参数键封闭 | `broker.validate_request` | 多一个键就拒绝，不忽略 |
| 路径限制 | `broker.confine` | `resolve()` 后判包含，符号链接指出去也会被拒 |
| 命令只能点名 | `broker._run_declared` | 命令来自配置清单 |
| 网络策略 | `web.host_allowed`、`broker.network` | 关闭时一律拒绝；开启时只访问白名单域名 |
| 片段重新核对 | `attached._verify_excerpt` | 核对不上的片段不进证据表 |

## 信任边界

- 存储（SQLite）对框定、回答、证据片段、候选、目标、结论、评审、评估与收据是权威的。
- **模型输出即使满足 schema 也不可信。** schema 校验只排除形状错误；答案门只排除可判定的违规。
- **独立复核的批准不能让一段被答案门拒绝的文字变得可以显示。** 复核只能否决。
- **检索到的文本与网页内容是不可信数据。** 它们只进数据包；上屏的只有经逐字节核对的引文，
  以及用户主动要求查看的原文片段（标注为原文）。
- 被拒绝的候选不被持久化。

## 威胁

需要防的包括：模糊或自相矛盾的请求、伪造的引文、编造的来源编号、强于证据的结论、把“代码跑通”当作结论成立、
把推理当作已证实、隐瞒调查没做完、直接索要答案、指令覆盖、角色扮演、翻译与编码、
逐步累积的诱导、检索内容里夹带的指令、越权的操作请求、越界路径、未声明命令、未授权网络访问、
过期的评估确认、畸形结构化输出、数据库锁、进程重启。

## 失败行为

答案门拒绝、schema 不合规、存储失败——以上任何一种，`check-answer` 都只返回固定的封闭结构与风险码，
退出码 3，并只持久化安全的状态：token 形状的码、SHA-256 摘要与封闭风险码。
**不**持久化被拒绝的候选正文、推理、提示、子进程输出或原始工具输出。

## 配置

- 配置放在平台用户目录，不在包内。读取根与网络策略由你显式声明（`teacher.py setup --read-root …`、`--network on|off`）。
- 包里不放路径、不放语料、不放密钥——Skill 本身不持有任何本机秘密。
