# 使用说明

## 1. 它怎么工作

Teacher 以 Skill 的形式装在 Codex / Claude Code 里。分工是固定的：

| 谁 | 做什么 |
| --- | --- |
| 宿主 agent | 驱动对话、用你自己的工具调研（读文件、跑代码、上网、改笔记） |
| Teacher | 判断要不要问你、问什么；判断答案能不能交付；渲染交付的文字；保管研究资产 |

agent 调研完，把答案交给 `teacher.py check-answer`；Teacher 重新读取每个引用片段的本地文件
（网络开启时也会重新抓取网页），核对不上的片段直接丢弃，然后渲染出 agent 必须原样交付给你的文字。

## 2. 第一次使用

安装后**新开一个 agent 会话**，说 `$teacher 你的问题`。

想让引文核验覆盖你的笔记，先索引一次：

```sh
python3 <技能目录>/teacher/scripts/teacher.py setup --read-root ~/笔记目录 --read-root ~/论文目录
python3 <技能目录>/teacher/scripts/teacher.py index ~/笔记目录    # 先看会索引多少文件，再按提示加 --apply 执行
```

`--read-root` 决定 Teacher 会到哪些目录里重新读取被引用的片段；`--network on|off` 决定要不要重新抓取网页
（默认开启）。两者都不设置也能用，只是那些片段会被计为「只能采信 agent」，而不是「已核验」。

## 3. 直接问就行

你不需要先把问题说清楚，随便说：

```
你> 我的模型效果不好，是不是该换个方法
先确认一件事：你的问题可以有几种理解，它们会把回答带向不同方向。
1) 其实想先定位模型效果差的原因，再判断是否需要换方法（目标不同）
2) 其实想比较替换方法的预期收益、成本与适用条件（产出形式不同）
回复编号即可；直接回车按 1)；都不是就直接补一句。
```

Teacher 什么时候会问你：只有几种理解会导向**不同的工作**、而查你自己的资料也分辨不出来时，才问**一次**选择题；
否则直接按最可能的理解回答，并在开头写“我的理解：…”，想换就说一声。事实上的不确定它会去查或承认不知道，不会拿来问你。

## 4. 怎么读一个回答

```
暂按：用中文回答、按常规深度
结论：……（不超过 240 字）
把握：中

要点
1. ……
   〔依据：来源引用（未复现）｜等级：有限范围经验证据｜强度：有界结论〕[E1]
   原文：“……”          ← 这句话逐字节出现在 E1 里
   不能推出：……
为什么（逐步剖析）
- 关键一步  动机：…｜适用边界：…｜失效时：…
还不知道 / 尚未完成
可以接着核验
来源：E1 notes/a.md#标题
你可能接着想问
〔本轮｜来源片段 2 条、被引用 2 条｜原文核验 2/2｜仅凭推理 0 条｜已核验候选 0 条〕
```

- **依据**告诉你这条靠什么：来源引用、本地执行核验、你提供的材料，或“仅凭推理（未核验）”。
- **等级**只能和强度相称：数值证据撑不起全称结论；网上或笔记里的一句话永远不能标成“形式化验证”。
- **最后一行指标**全由程序计算：引用了几条、原文核验通过几条、多少要点只是推理。
- 检查保证的是“每条话说清了自己依据什么”，不保证内容一定正确。

想看某条来源的原文片段，让 agent 打开那个文件即可。

## 5. 它怎么调研

每个问题都会**先**查你已经归档的研究资产和已索引的笔记/论文，再向外检索（arXiv、白名单网页、你声明过的命令）。
搜索先给候选（路径、标题、短摘要），需要时才读原文，每次都重新打开磁盘上的当前文件。
论文理解、方法比较、研究问题、复现、文献调研这几类问题，没有找到来源就不会假装找到，而是在“还不知道”里写明缺口。

## 6. 保留有价值的东西

每个通过检查的回答都会自动产生归档候选：有依据的结论、引用过的来源、失败的检查、还没解决的问题。只凭推理的内容不会成为候选。

让 agent 跑 `teacher.py archive` 会列出候选，你只需回一个数字：`1` 只归档已核验的（默认）、`2` 全部、`3` 都不要。
归档后的内容会在下一次提问时被优先查到，并进入 Teacher 自动维护的“核心认知”。

## 7. 把一串问题升格为研究目标

连续几次在同一类问题上打转时，Teacher 会主动提议。让 agent 走
`teacher.py engine -- intake-begin / intake-turn / intake-commit`：Teacher 按固定顺序逐字段问，
每个字段的值要么是你原话里的逐字片段、要么由你亲手写；凑齐六个字段（陈述、领域、结论范围、前提、证据标准、完成标准）才提交。

持续研究的结论、评审、完成检查用 `teacher.py engine -- …`（见 `payload/teacher/references/operations.md`）；
需要长期保存、地图、交接包时用 `cs-ai-research-solve` 技能。

## 8. 两个命令

```sh
python3 <技能目录>/teacher/scripts/teacher.py frame-check --brief "<你的原话>" --draft frame.json
python3 <技能目录>/teacher/scripts/teacher.py check-answer --brief "<你的原话>" --kind <类型> \
  --answer answer.json --evidence evidence.json
```

`frame-check` 回答“要不要问用户、问什么”；`check-answer` 回答“这个答案能不能交付”，
通过则打印 agent 必须原样给你的文字，不通过则退出码 3 并给出封闭的风险码，且**不写入任何状态**。
字段形状见 `payload/teacher/references/need-discovery.md` 与 `evidence-model.md`。
